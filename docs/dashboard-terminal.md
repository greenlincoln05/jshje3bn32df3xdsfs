# Trading terminal

Start with `btcbot dashboard --data-dir <recording-directory> --port 8766` from this checkout. The server binds only to 127.0.0.1. It monitors local recordings and does not place or cancel exchange orders.

- **Overview:** YES/NO depth, implied asks, native/1¢/5¢ grouping, cumulative contracts and actual notional, spread, full-book bid share, top-level microprice, and a pre-fee liquidity estimate. The charts cover the selected market window with at most 400 time samples. Hover for timestamps and values.
- **Clock:** UTC system time and expiration countdown show milliseconds. Display updates follow browser frames; this is not exchange clock synchronization or a guarantee of millisecond feed accuracy. Book/spot age refer to local recorder timestamps. Request latency and local dashboard RTT are separate measurements.
- **Portfolio:** settled net PnL, starting account (found automatically: the run's own `account_start` log, then `config.yaml`'s `sizing.account_usd` -- no manual entry needed), growth, fees, win rate, profit factor, drawdown, recorded exposure, and windows traded (distinct 15-minute markets with a recorded fill) of windows seen (distinct markets recorded at all, traded or not). Reference equity is not an exchange account balance. Unresolved PnL is not guessed. Metrics include the complete ledger; the newest 200 trades are searchable and exportable. Chart range changes the chart only. Settlement observation timestamps are used where complete; otherwise entry-time ordering is explicitly labeled as a proxy.
- **Active orders:** demo state comes from the local order ledger and is not exchange-verified. Updated paper recorders persist resting orders, partial fills, queue state, and held/pending positions in a single-row `paper_runtime` snapshot. Existing running processes must be restarted using the updated checkout to begin emitting this snapshot; older files display unavailable resting-order tracking. No process is automatically restarted. Snapshot age and stopped state are displayed.
- **Backtest:** a bounded worker runs offline sensitivity scenarios without blocking HTTP requests. Progress counts completed scenarios. Queue/fee variants read a consistent SQLite snapshot. Completed runs can be reused while the recording, WAL, and configuration remain unchanged. Results identify the source file even if you switch selections while a replay is running. Strategy Lab retains chronological training/holdout evaluation; its account-size/risk fields default from `config.yaml`, not a hardcoded guess, and its recording checklist excludes Polymarket recordings (a separate venue, `pm_`-prefixed schema -- see `btcbot record-polymarket` in CLAUDE.md).
- **Settings:** the Kalshi env/key panel this dashboard has always had, plus a "Trading config" panel that reads and edits a small, numeric-only allowlist of `config.yaml` values (account size, risk caps, min edge, min/max entry price, contracts) -- `sizing.mode` itself stays a file edit on purpose. Every edit is validated before anything is written; the raw YAML text is patched line-by-line so comments and formatting survive, never a full re-serialize.
- **Perps (paper):** the same bounded-worker, offline-compute pattern as Backtest, for `btcbot perp-backtest` (docs/research/perps-paper.md) instead of the 15-minute Kalshi market. Lists local databases with usable BTC bars (a `download-history` file's Coinbase candles, or a `download-polymarket-history` file's Binance klines) and runs a fresh backtest over one in the background, or reloads any `perp-backtest-*.json` report already saved under `data/research/` (by this tab or by the CLI -- both write and read the same file). Same guarantees as the CLI: no network, no key, and no perps order code exists anywhere in this repo.

Quotes use indexed reads at up to one request every 150 ms, with no overlapping requests. Chart, portfolio, and order panels refresh every three seconds; hidden browser tabs stop routine refreshes. The clock continues independently of data polling. The dashboard uses no third-party scripts, fonts, analytics, or CDN requests.

Validation: run `python -m pytest` and `node tests/dashboard_sync.cjs`, `node tests/dashboard_terminal.cjs`, `node tests/dashboard_perps.cjs`. Tests cover read-only queries, binary depth conversion, bounded history, settled accounting, the active paper-order lifecycle, async job consistency, HTTP validation, and frontend numeric behavior.
